# 0.1.4 — 2026-09-21

## Changed

- **`MCP_SESSION_MODE`** is `stateful` in the Docker image (previously `stateless`) and set actively in `.env.example` (previously commented out), and the server declares `createApp({ sessionMode: { default: 'stateful', require: 'stateful' } })`. An HTTP start with `MCP_SESSION_MODE=stateless` now fails at startup with a configuration error; an unset variable already resolved to `stateful`, and stdio is unaffected. (#8)
  - Why: `evals_submit_draft`'s confirmation (`confirm: true` or `EVALS_REQUIRE_CONFIRMATION`) is a multi-round input request that a 2025-era HTTP client can answer only over a live session.
  - Migration: unset `MCP_SESSION_MODE` or set it to `stateful`.
- **Argument-rejection error envelope** (mcp-ts-core 0.12.7, 0.13.3, 0.13.5): an argument rejection returns the structured `-32602` envelope; 0.13.3 adds `data.reason: "invalid_arguments"` and a `Recovery:` line, and 0.13.5 closes the tool error text with the reason in parentheses. Observed for an undeclared key on `evals_get_record`: `Unrecognized key: "bogus"` → `Recovery: Unknown key bogus. This tool accepts: id.` → `(reason invalid_arguments)`. Advertised `inputSchema`/`outputSchema` unchanged — `tools/list` is byte-identical to 0.1.3.
- **Input normalization before validation** (mcp-ts-core 0.13.4): a case-style variant of a declared key is rewritten before validation (`draftId` accepted as `draft_id`), and a JSON-stringified array is repaired (`candidates: "[\"5\", \"6\"]"` graded as an array).
- **`evals_submit_draft` needs elicitation capability for `confirm: true`** (mcp-ts-core 0.13.5): a `2025-11-25` client that declares no elicitation capability gets `-32600`, `data.reason: "client_capability_missing"`, with a recovery hint naming `elicitation.form`; the draft stays a draft.
- **Resolved session mode on the server card** (mcp-ts-core 0.13.2): `/.well-known/mcp.json` carries it at `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` — observed `stateful`.
- **`verification_disagrees_with_gold` forwards its contract recovery hint** on the wire — previously that throw site forwarded none.
- **Internal:** development skill tree moved to `framework-skills/` (`skills/` was never in the npm `files` allowlist, so it never shipped); `thrownBy: 'service'` lint-only markers added across every typed error contract; new lint rules, scripts/tooling sync, and a serialized vitest integration test project for the boot/confirmation behavior above.

## Fixed

- **An unsubstituted `${user_config.evals_data_dir}` placeholder now falls back to the default data dir** (mcp-ts-core 0.13.0): `parseEnvConfig` reads a blank or whole-value `${…}` placeholder as unset, same as an unset variable; the server's own blank-only guard was redundant and removed.
