# 0.1.5 — 2026-10-07

## Changed

- **Framework input recovery** decodes JSON-stringified objects and converts safe integers sent for string fields before rejecting arguments (mcp-ts-core 0.13.9).
- **Error envelopes** fill declared recovery hints and carry request IDs (0.13.10); framework-generated `data.rootCause` no longer reaches callers (0.13.13).
- **Maintenance** syncs framework skills and validation scripts, documents opt-in request-state sealing and telemetry, excludes caches/logs from bundles, and aligns CodeQL categories.

## Fixed

- **Docker storage** prepares `/usr/src/app/evals-data` for the runtime user, matching the default record directory; examples mount that path ([#14](https://github.com/cyanheads/evals-mcp-server/issues/14)).
- **Multi-architecture images** install target dependencies on the build platform, install OTel peers at framework ranges, and remove musl-only bindings from the glibc runtime.
- **MCP Registry launch metadata** uses `npx` without npm-script arguments and fixes `MCP_TRANSPORT_TYPE=http` for the HTTP entry.

## Security

- **Submit confirmation** requires a server-issued, 10-minute consent record bound to the operation, authenticated caller, draft ID, and complete draft; edits invalidate consent and consumed rounds cannot be replayed sequentially ([#13](https://github.com/cyanheads/evals-mcp-server/issues/13)). Concurrent retries still require serialization.
